# The image: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the sync deployable: an image CI publishes to GHCR from `main`, plus the code the first production runs need (a first success needs the user present; the two minors the import left).

**Architecture:** A single-stage image of the server's source on the official Node 24 image, with a `money` command and an idle default command; a shell script that checks a built image by running it; two CI jobs (check everywhere, publish from `main`). In `sync`, the inbox marker gains `attended`, and a completed longest-period run records a success only when attended.

**Tech Stack:** Node 24 running TypeScript directly, `node:test`, Docker, GitHub Actions, POSIX shell and bash.

**Spec:** `docs/specs/2026-10-14-image.md`

## Global Constraints

- No new dependency of any kind, and no new GitHub Action. The jobs use `docker` and `actions/checkout` as already pinned.
- Every invented IBAN uses check digits `00`. Examples use made-up banks (`bnka`, `Example Bank`). No bank, host, volume, network or container name of production appears anywhere.
- Printed lines hold counts, dates and keys only.
- Erasable TypeScript only; relative imports carry `.ts`; type-only imports use `import type`.
- Conventional commits; every commit passes the pre-commit hook (typecheck, lint, format check, full suite). Never `--no-verify`. End each commit message with `Claude-Session: https://claude.ai/code/session_01GxtnSpLRuDVEEsgHiLjNg8`.
- Base image: `node:24.21.0-slim@sha256:d6aa754f16b3197301076f047b5def2f02ea1dbbc2ca920407d46d7ec7f87b20` (confirmed on 2026-10-14 to be the digest of both `node:24-slim` and `node:24.21.0-slim`; Node v24.21.0, user `node` uid 1000, GNU `sleep` that accepts `infinity`).
- The sync's new failure line, verbatim: `<account>: fetched without a first success, so the bank gave only what it serves unattended. Run: auth <bank>`.
- The reader's new refusal, verbatim: `row <n> has a carriage return that does not end a line`.
- Run tests through `npm test` (it pins `TZ`). A single file: `TZ=Europe/Amsterdam node --test <file>`.
- On this machine `docker build` needs `DOCKER_BUILDKIT=0` (buildx is not installed). CI runners have BuildKit; nothing in the Dockerfile depends on either.

## Review Focus

1. **The `publish` job can only be proven by the push to `main`.** Its permissions, the lower-cased image name and the login are untestable on a branch. The reviewer reads the YAML against GitHub's documented `permissions` and `GITHUB_TOKEN` behaviour; the integration step watches the run.
2. **A sandbox inbox written before this slice** holds markers without `attended` and is refused by name. Expected: refused, never misread as attended. Pinned by the inbox test in Task 1.
3. **A completed attended run left in the inbox, merged by an unattended `sync`,** must record its success, since the user was present when it was fetched. Pinned by a Task 1 account test.
4. **A file whose lines end in a carriage return alone** must be refused as such, not as "a header and no rows". Pinned by a Task 2 test.
5. **A mounted directory created by another user** (CI's runner uid 1001 against the image's uid 1000): the import check in `check-image.sh` must make what it mounts readable, or it fails on Linux and passes on a Mac. The script `chmod`s explicitly; Task 4's CI run proves it on Linux.

- [ ] **Step 1: Write the check first**

Create `scripts/check-image.sh` (then `chmod +x scripts/check-image.sh`):

```bash
#!/usr/bin/env bash
# Checks a built image the way the host will use it, by running it.
#
#   scripts/check-image.sh <image>
#
# Everything it gives the image is made up here and thrown away: a key generated for the
# run, a configuration of invented banks, and an export of one invented row.
set -euo pipefail

if [ "$#" -ne 1 ]; then
    echo "usage: scripts/check-image.sh <image>" >&2
    exit 2
fi
IMAGE=$1

# Under the checkout and not the system's temporary directory, which Docker on a Mac
# cannot mount. Ignored by git, and removed on exit.
WORK=$(mktemp -d "$PWD/.image-check.XXXXXX")
trap 'rm -rf "$WORK"' EXIT

fail() {
    echo "FAIL: $1" >&2
    exit 1
}
ok() { echo "ok   $1"; }
run() { docker run --rm "$@"; }

# 1. With no command, the usage line, and a failure: a job that typed it wrong must alert.
if out=$(run "$IMAGE" money 2>&1); then fail "money with no command exited 0"; fi
grep -q '^usage: auth <bank>' <<<"$out" || fail "money with no command did not print the usage line"
ok "money with no command prints the usage line and fails"

# 2. Without configuration, every command refuses to start, and says what is missing.
if out=$(run "$IMAGE" money status 2>&1); then fail "money status without configuration exited 0"; fi
grep -qx 'CONFIG_PATH is not set' <<<"$out" || fail "money status did not name the missing CONFIG_PATH"
ok "money status without configuration names what is missing"

# 3. The directories volumes are mounted over belong to the user the image runs as.
run "$IMAGE" sh -c '
    for dir in /data /state; do
        [ "$(stat -c %U "$dir")" = "$(id -un)" ] && [ -w "$dir" ] || exit 1
    done' || fail "/data and /state are not owned and writable by the image's user"
ok "/data and /state are owned and writable by the image's user"

# 4. The application directory holds the source and the workspace links, and nothing else.
listing=$(run "$IMAGE" sh -c 'ls -A /app | tr "\n" " "; echo; ls -A /app/node_modules | tr "\n" " "')
[ "$(sed -n 1p <<<"$listing")" = "node_modules package-lock.json package.json shared sync " ] \
    || fail "/app holds more or less than the source: $(sed -n 1p <<<"$listing")"
[ "$(sed -n 2p <<<"$listing")" = ".package-lock.json @money " ] \
    || fail "node_modules holds more than the workspace links: $(sed -n 2p <<<"$listing")"
ok "/app holds the source and the workspace links only"

# 5. No test, test helper, fixture or environment file reached the image.
found=$(run "$IMAGE" find /app -name node_modules -prune -o \
    \( -name '*.test.ts' -o -name testing -o -name fixtures -o -name docs -o -name tmp -o -name '.env*' \) -print)
[ -z "$found" ] || fail "the image holds what it must not: $found"
ok "no tests, fixtures, docs or environment files"

# 6. An import check, through the configuration and the store: the one run that crosses
#    every workspace inside the image. The mounted directory is readable by any user,
#    because the image does not run as the user that created it.
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out "$WORK/key.pem" 2>/dev/null
mkdir "$WORK/import"
cat >"$WORK/import/config.json" <<'JSON'
{
  "banks": { "bnka": { "aspsp": { "name": "Example Bank", "country": "NL" } } },
  "accounts": { "bnka-current": { "bank": "bnka", "iban": "NL00BNKA0000000001" } },
  "imports": {
    "example-export": {
      "delimiter": ";",
      "encoding": "utf-8",
      "account": { "column": "Account" },
      "id": { "column": "Sequence" },
      "date": { "column": "Booked", "format": "YYYY-MM-DD" },
      "amount": { "column": "Amount", "decimal": "," },
      "currency": { "column": "Currency" }
    }
  }
}
JSON
printf 'Account;Sequence;Booked;Amount;Currency\r\nNL00BNKA0000000001;1;2025-01-02;-12,34;EUR\r\n' \
    >"$WORK/import/export.csv"
chmod 755 "$WORK/import"
chmod 644 "$WORK/import/config.json" "$WORK/import/export.csv"
out=$(run \
    -e EB_APP_ID=00000000-0000-4000-8000-00000000aaaa \
    -e "EB_PRIVATE_KEY=$(base64 <"$WORK/key.pem" | tr -d '\n')" \
    -e EB_REDIRECT_URL=https://localhost/auth-callback \
    -e CONFIG_PATH=/import/config.json \
    -v "$WORK/import:/import:ro" \
    "$IMAGE" money import example-export /import/export.csv 2>&1) \
    || fail "an import check failed: $out"
grep -qx 'import-checked format=example-export accounts=1 rows=1 written=no' <<<"$out" \
    || fail "an import check did not print its summary: $out"
ok "an import check reads a mounted file and prints its summary"

echo "image checked"
```
